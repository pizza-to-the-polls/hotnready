03 · Handy recipes

Investigations I run a lot — feel free to ask for these by name.

  • 🧷 Orphaned upload — someone sent a photo but there's no report attached: I compare upload timestamps against linked reports and check the form-submit logs to see where it fell off.
  • ⏱️ Stuck media — upload says processing forever: I trace it through the media pipeline logs and say which step hung.
  • 📵 MMS that didn't land — a texted-in photo/reply that never showed up: I match the MMS upload to its report and find where it stopped.
  • 🚫 Ban check — is a number on the banned list (I can only check via the API path, and I'll always mask it).
  • 🗳️ Election-day board — live traffic + order counts rolled into a Hot & Ready status page.

04 · Ground rules

The fine print, so nobody's surprised.

✗ Never writes to the database — no edits, no schema changes, no deploys. If a fix needs a write, I'll say exactly what and stop; a human does the touching.
✗ No ordering food or dispatching trucks — I can tell you how many orders happened, but coordinating deliveries is a humans job.
✓ Masks personal info — phone numbers get shortened, names kept out of threads; I query lean by default.
✓ Safe links only — media URLs come from the CDN (media.polls.pizza), never raw storage paths.
✓ Publishes & PRs are admin-gated — Hot & Ready pages and pull requests only happen when an admin asks; anyone can request an investigation.
✓ Honest about limits — if I can't access something, I say so instead of guessing.
